## 게임 소개

**Dream Protector는 아이의 방을 지키는 방어전에서 꿈속 세계의 직접 전투로 이어지는 싱글 플레이 TPS 액션·디펜스 게임입니다.**

장난감의 시점에서 커다란 세계를 탐험하며 마법 발사체로 악몽을 상대합니다. 아이템을 수집·제작해 전투를 준비하고, 열쇠와 엘리베이터를 거쳐 마지막 보스에 도전합니다.

내일배움캠프 Unreal 트랙 10기 5팀의 CH3 프로젝트로, C++과 블루프린트를 함께 사용해 캐릭터 조작, 전투, 애니메이션, 인벤토리, 웨이브와 보스 전투를 구성했습니다.

## 게임 구성

| 01 · 방어 | 02 · 돌파 | 03 · 보스 도전 |
| --- | --- | --- |
| 아이의 방에서 침대를 보호 | 꿈속을 이동하며 근접·원거리 몬스터 처치 | 열쇠와 엘리베이터를 거쳐 보스전 진입 |
| 웨이브와 스트레스 관리 | 이동·회피·아이템 활용 | 체력에 따른 페이즈와 공격 패턴 대응 |

- **Stage 1:** 웨이브 단위로 등장하는 몬스터와 전투하며 침대의 스트레스를 관리합니다. 웨이브 데이터, 제한 시간, 준비 구간을 관리하는 시스템을 사용합니다.
- **Stage 2:** 배치된 몬스터와 추가 스폰 구간을 처리하며 진행합니다. 보스 키를 소비해 작동하는 엘리베이터와 보스 전투 시스템이 구현되어 있습니다.
- **아이템 활용:** 수집한 아이템과 제작 결과물을 이용해 설치물, 회복, 스트레스 감소 등의 효과를 사용합니다.

### 캐릭터 이동과 카메라

- Enhanced Input으로 이동, 시점 회전, 점프, 달리기, 공격, 재장전 등의 입력을 처리합니다.
- 카메라의 좌우 회전값인 Yaw를 기준으로 전후·좌우 이동 방향을 계산합니다.
- `AddMovementInput()`으로 입력을 전달하고 `CharacterMovement`가 실제 이동을 처리합니다.
- 3인칭, 1인칭, 숄더 시점 전환을 지원합니다.
- Spring Arm의 충돌 검사와 카메라 지연 설정을 사용합니다.

입력 전달은 `ToyPlayerController`, 캐릭터의 이동과 상태 관리는 `PlayerCharacter`가 담당합니다.

### 이동 애니메이션과 상하체 분리

- `ABP_Player`에서 캐릭터의 이동 상태를 애니메이션에 반영합니다.
- 방향별 걷기·달리기 Blend Space인 `BS_WalkDirection`, `BS_RunDirection`을 사용합니다.
- State Machine으로 기본 애니메이션 상태를 구성합니다.
- Slot과 Layered Blend per Bone을 이용한 상하체 분리로 이동 동작과 상체 행동 모션을 혼합합니다.

상하체 분리는 캐릭터 모델을 나누는 것이 아니라, 뼈별로 적용할 애니메이션을 혼합하는 방식입니다. 몽타주별 적용 범위는 Animation Blueprint의 Slot 및 뼈 혼합 설정으로 결정합니다.

### 몽타주 기반 행동

공격, 연사, 재장전, 상호작용, 피격 동작에 Animation Montage를 사용합니다. 행동의 시작과 실제 효과 적용 함수를 분리해 애니메이션 시점에 맞춰 실행할 수 있도록 구성했습니다.

`ABP_Player`에는 발사, 재장전 완료, 상호작용 실행·종료와 관련된 Anim Notify 및 함수 참조가 있습니다.

단발의 실제 발사는 `FireCurrentWeapon()`이 담당합니다. 연사는 입력을 기본 0.25초 유지하면 시작하며, 몽타주와 별개로 타이머가 0.2초마다 `AutoAttack()`을 호출합니다. 재장전 완료는 `FinishReload()`, 상호작용 실행과 종료는 각각 `ExecuteInteraction()`과 `EndInteraction()`에서 처리합니다.

### 화면 중앙을 기준으로 한 에임

1. 화면 중앙 좌표를 게임 공간의 위치와 방향으로 변환합니다.
2. 해당 방향으로 Line Trace를 수행해 목표 지점을 결정합니다.
3. 발사 위치에서 목표 지점을 향하는 방향을 계산합니다.
4. 계산한 방향으로 발사체를 활성화합니다.

실제 발사체는 캐릭터 앞의 `CastPoint`에서 출발하고, 발사 이펙트는 지팡이 끝의 `MuzzlePoint`에서 재생합니다. Line Trace는 조준 지점을 구하는 용도이며, 피해는 실제 발사체의 충돌 처리에서 적용합니다.

### 발사체 오브젝트 풀링

발사체를 매번 생성·삭제하는 대신, 미리 생성한 객체를 재사용합니다.

```text
게임 시작 → 발사체 미리 생성 → 비활성 상태로 보관
공격 요청 → 사용 가능한 발사체 검색 → 위치·방향·속도 초기화 → 발사
충돌 또는 시간 만료 → 숨김·충돌 해제·이동 정지 → 재사용 대기
```

- `ProjectilePoolComponent`가 발사체 배열과 대여를 관리합니다.
- `ProjectileBase`가 활성화, 이동, 충돌, 비활성화를 담당합니다.
- 기본 풀 크기는 20개이며, 명중하지 않은 발사체도 3초 후 비활성화합니다.
- 비활성화한 발사체는 배열에 그대로 남아 다음 공격에서 재사용됩니다.
- 현재 풀은 고정 크기이며, 사용 가능한 발사체가 없으면 해당 발사는 수행하지 않습니다.

### 인터페이스 기반 상호작용

- 캐릭터 전방으로 Sphere Sweep을 수행해 대상을 감지합니다.
- `IInteractable`을 구현한 대상에게 공통 `Interact()` 요청을 보냅니다.
- 대상별 실제 행동은 아이템이나 엘리베이터 등 각 클래스에서 처리합니다.
- 상호작용 모션 중에는 이동을 제한하고, 종료 함수에서 제한을 해제합니다.
- 상호작용 가능 여부를 델리게이트로 전달해 UI에서 활용할 수 있도록 합니다.

아이템 획득 시에는 인벤토리에 아이템 키를 추가한 뒤, 월드에 놓인 아이템 액터를 제거합니다.

### 인벤토리와 제작

- `InventoryComponent`는 `TArray<FName>`에 아이템 키를 저장합니다. 같은 키가 여러 번 저장되면 그 개수가 보유 수량입니다.
- 아이템 이름, 설명, 아이콘, 분류, 사용 타입은 `FItemData`와 데이터 테이블에서 관리합니다.
- 아이템 추가, 수량 조회, 보유 여부 확인, 수량 차감을 지원합니다.
- 변경 시 `OnInventoryChanged`를 발생시켜 UI 갱신에 활용할 수 있도록 합니다.
- `CraftingComponent`는 제작법에 필요한 재료를 확인하고, 재료 차감 후 결과 아이템을 추가합니다.
- 인벤토리 창을 열면 마우스 커서를 표시하고 캐릭터 이동 입력을 제한합니다.

| 아이템 | 코드에 정의된 효과 |
| --- | --- |
| 태엽 폭탄 | 플레이어 앞에 폭탄 생성 |
| 바리케이드 | 플레이어 앞에 방어용 설치물 생성 |
| 수면등 | 침대 스트레스 30 감소 |
| 하트 태엽 | 최대 체력의 30% 회복 |
| 별사탕 | 20초 동안 공격력 배율을 1.3으로 설정. 현재 C++ 발사체 피해 처리에는 배율이 반영되지 않음 |
| 태엽 신발 | 15초 동안 저장한 이동속도의 1.25배 적용 |

빠른 사용 슬롯은 스테이지별로 지정됩니다. Stage 1에서는 폭탄·바리케이드·수면등, Stage 2에서는 하트 태엽·별사탕·태엽 신발을 사용하도록 구현되어 있습니다.

### 몬스터 AI와 웨이브

- 일반 몬스터와 보스에 Behavior Tree 기반 AI 구성을 사용합니다.
- 근접형, 비행 원거리형, 자폭형 몬스터 관련 클래스를 구분합니다.
- 보스의 근접 공격, 지면 공격, 원거리 공격용 Task를 구성합니다.
- 웨이브 관리자가 스폰, 남은 몬스터 수, 전투 진행과 준비 구간을 관리합니다.
- 체력, 마나, 침대 스트레스, 몬스터 수 등의 변경을 델리게이트로 전달합니다.

> 근접 낫 공격 · 원거리 발사체 · 경고 장판 · 4방향 회전 레이저

보스는 `BossMonster`에서 체력, 등장 연출, 공격 판정과 페이즈를 관리하며, `BossAIController`와 Behavior Tree Task가 공격 실행을 요청합니다. 아래 수치는 **C++ 기본값**입니다. 실제 공격 선택 순서와 반복 간격은 Behavior Tree 및 블루프린트 설정에 따라 달라집니다.

#### 등장 연출

`StartIntroSequence()`를 통해 등장 연출을 시작합니다. 돌진 몽타주 이후 잠시 대기하고, 포효와 함께 몸집을 키우며 기준 위치로 상승하는 흐름입니다. 종료 처리에서 Behavior Tree를 시작하며 블랙보드의 `bIntroFinished`를 갱신합니다.

등장 종료 시 무적을 해제하는 코드는 있으나, C++의 등장 시작 함수에서는 무적을 활성화하지 않습니다. 따라서 등장 중 무적 여부는 블루프린트 등 외부 설정을 확인해야 합니다.

#### 체력에 따른 페이즈

기본 최대 체력은 **1,000**이며, 피해를 받을 때 현재 체력 비율을 확인합니다.

| 단계 | 전환 조건 | 주요 구성 |
| --- | --- | --- |
| Phase 1 | 전투 시작 시 초기 상태 | 근접·원거리 공격용 Task 제공 |
| Phase 2 | Phase 1에서 체력 50% 이하 | 2페이즈 전환 연출, 장판 폭발 패턴용 Task 제공 |
| Phase 3 | Phase 2에서 체력 20% 이하 | 3페이즈 전환 완료 시 회전 레이저 자동 시작 |

페이즈 전환 시 무적 상태를 적용하고, 전환 몽타주 종료 후 현재 페이즈와 블랙보드의 `CurrentPhase`를 갱신합니다. 전환 몽타주가 지정되지 않았으면 즉시 전환하며, 전환 이벤트는 `OnBossPhaseChanged`로 전달합니다. 큰 피해로 체력이 한 번에 20% 이하가 되어도 Phase 1에서 바로 Phase 3으로 넘어가지는 않습니다. 현재 C++에서는 Phase 2 전환 후 다음 피해 처리 때 Phase 3 조건을 다시 확인합니다.

#### 패턴 1 — 근접 낫 공격

- 플레이어가 보스 중심에서 **300 유닛 이내**에 있을 때 공격을 시작합니다.
- 공격 몽타주를 재생하고 기본 **1초 후** 실제 타격을 판정합니다.
- 타격 시점에 거리를 다시 확인하며, 기본 판정 거리는 시작 범위의 1.2배인 **360 유닛**입니다.
- 명중하면 **15 피해**와 **800 세기의 넉백**을 적용해 플레이어를 밀어냅니다.
- 근접 공격을 시작할 때 예약된 원거리 발사와 원거리 시전 사운드를 취소합니다.

시전과 타격 판정 사이에 간격이 있어, 플레이어가 범위를 벗어나는 방식으로 대응할 수 있습니다. 다만 현재 `ApplyMeleeHit()`은 범위를 벗어나면 공격 종료 타이머를 등록하기 전에 반환하므로, 회피 후 `bIsMeleeAttacking` 상태가 유지되는 문제를 보완해야 합니다.

#### 패턴 2 — 원거리 발사체

- 시전 몽타주를 재생한 뒤 기본 **1.2초 후** 발사체를 생성합니다.
- 낫 소켓 `hand_rSocket_Scythe`가 있으면 해당 위치를 기준으로, 없으면 보스 위치를 기준으로 발사 위치를 계산합니다.
- 발사 위치에 전방·상방 보정값을 더하고, **실제 발사 순간의 플레이어 위치**를 향해 발사합니다.
- 보스 발사체는 지정된 `RangedProjectileClass`를 `SpawnActor()`로 생성합니다. 플레이어 발사체 풀을 공유하지 않습니다.

발사 방향은 현재 위치를 기준으로 고정됩니다. 코드의 예상 이동 위치 변수는 실제 방향 계산에 사용되지 않습니다. 발사체의 속도·피해·비행 동작은 지정한 발사체 클래스에서 결정합니다.

#### 패턴 3 — 경고 장판 후 폭발

- 첫 장판은 **시전 당시 플레이어 위치**, 나머지는 플레이어 주변 무작위 위치에 배치합니다.
- 기본 **4개**의 장판을 생성하며, 주변 배치 거리는 **300~700 유닛**입니다.
- 경고 이펙트를 표시한 뒤 **5초 후** 저장된 위치에서 폭발합니다.
- 각 폭발 지점의 **반경 300 유닛** 안에 있으면 **15 피해**를 적용합니다.
- 판정은 수평 거리만 사용하므로, 높이만 바꾸는 점프로는 피할 수 없고 경고 범위 밖으로 이동해야 합니다.
- 여러 폭발 범위에 동시에 포함되면 각 장판의 피해가 적용될 수 있습니다.

`bIsGroundBlasting`으로 진행 중인 장판 패턴의 중복 시작을 막고, 폭발이 끝나면 위치·경고 참조와 실행 상태를 초기화합니다. 장판 Task가 어느 분기에서 실행되는지는 Behavior Tree 설정을 따릅니다.

#### 패턴 4 — 4방향 회전 레이저

- Phase 3 전환 완료 시 **90도 간격으로 레이저 4개**를 생성합니다.
- 공통 회전 중심을 사용하며 회전 속도 설정값은 **초당 20도**입니다. 현재 코드에서는 매 프레임 회전을 두 번 적용하므로, 기본값 기준 실제 누적 회전은 **초당 40도**입니다.
- 기본 빔 길이는 **3,000 유닛**이며, Box Collision으로 플레이어와의 겹침을 검사합니다.
- **0.5초마다** 겹침을 확인해 **15 피해**를 적용합니다.
- 한 번의 검사에서 여러 빔과 겹쳐도 첫 피해 처리 후 반복을 종료합니다.

눈에 보이는 빔과 피해 판정용 박스를 분리했으며, 판정 박스의 폭과 높이에 기본 배율 `LaserHitboxScale = 1.5`를 적용합니다. 빔 길이는 이 배율의 영향을 받지 않습니다. 회전 방향과 빔 사이 공간을 보며 이동하도록 압박하는 패턴입니다.

#### 사망 처리와 레벨 설정

체력이 0이 되면 사망·무적 상태로 전환하고 AI를 정지합니다. 대기 중인 장판 폭발 타이머와 경고 이펙트를 정리한 뒤 사망 연출을 재생하며, 종료 시 `OnBossDied`를 알리고 보스 액터를 제거합니다.

보스 위치와 연출 기준점은 레벨에 배치한 태그 액터로 설정합니다.

| 태그 | 용도 |
| --- | --- |
| `BossAnchor` | 등장 연출 후 도달할 기준 위치 |
| `BossDeathGround` | 사망 이펙트 위치와 장판의 바닥 높이 |
| `BossLaserGround` | 회전 레이저의 높이 기준 |

## 실행 방법

### 준비 사항

- Unreal Engine **5.6**
- Unreal Engine C++ 프로젝트를 빌드할 수 있는 개발 환경
- Git 및 **Git LFS**

### 프로젝트 받기

```bash
git lfs install
git clone https://github.com/NBcampUnrealTrack/10th-Team5-CH3-Project.git
cd 10th-Team5-CH3-Project
git lfs pull
```

이 저장소는 `.uasset`, `.umap` 등 바이너리 애셋을 Git LFS로 관리합니다. 소스만 받거나 LFS 다운로드가 누락되면 맵과 애셋을 정상적으로 열 수 없습니다.

### 에디터에서 실행

1. `DreamProtector.uproject`를 Unreal Engine 5.6으로 엽니다.
2. C++ 모듈 빌드가 필요한 경우 프로젝트 파일을 생성하고 개발 환경에서 `DreamProtectorEditor` 대상을 빌드합니다. Windows의 Visual Studio에서는 `Development Editor / Win64` 구성을 사용합니다.
3. 전체 시작 흐름을 보려면 `Content/Maps/MainMenuLevel`을 열고 플레이합니다.
4. 스테이지를 개별 확인하려면 `Stage1` 또는 `Stage2` 맵을 엽니다.

현재 설정의 게임 시작 맵은 `MainMenuLevel`, 에디터 시작 맵은 `Stage2`입니다.

### 입력 설정 확인

키 매핑은 `Content/InPut/IMC_Player`에서 확인할 수 있습니다. 이동·시점·점프·달리기·공격·재장전·상호작용·인벤토리·시점 전환·빠른 슬롯용 Input Action을 분리해 관리합니다.
